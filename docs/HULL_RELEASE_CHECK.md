# Use the published Hull build in your existing Windows checkout

**Goal:** test a known revision and inspect the real Windows MT5 **USD hedging demo** account, without starting a scanner or sending an order. No new repo, worktree, or Journal is required. A Journal HTTP 200 only proves a page is being served.

1. **Identify the current folder before changing anything.** In VS Code PowerShell run `git rev-parse --show-toplevel`, `git remote -v`, `git status --short --branch`, then `git fetch origin` and `git rev-parse origin/main`. Compare to the **full published SHA supplied with the release**, not just `HEAD`. If the remote has advanced, review that separately. Do not derive the expected SHA from the checkout you are trying to verify.
2. **Protect existing work and running services.** If the editor checkout is dirty, have the desktop agent preserve the tracked/staged diff *and* inventoried untracked work in a secure, verified local backup. A branch name alone does not save uncommitted files. Keep private YAML, its `.targets.json`, terminal settings, audit logs and account/Journal state private; never `git add -A` them or overwrite them with the template. Do not apply the local bot diff over the tested release. If a Journal is serving from files about to change, arrange a reporter-only handoff before modifying those files (same `--out`, `--repo` and magic, no duplicate writer). Never stop an unknown scanner or interrupt open/pending/unreconciled positions to update. Do not force-pull, hard-reset or clean. Once the old work is preserved and the tracked tree clean, on the intended `main` use `git pull --ff-only origin main`. If this cannot fast-forward safely, report the blocker instead of rewriting history.
3. **Verify the operator config, not just the template.** The paper template ships `hull.pairs: {5: 4, 10: 8, 15: 12}` and `by_route` (intrabar for paired market). The same map is used when `pairs` is omitted. If the existing private file explicitly says `confirmed_cross_next_bar`, it still means **closed-only**. With no affected scanner or open/pending/uncertain trades, back up the private file, keep its enabled symbols, magic, aliases, sizes, saved target overrides, caps and sessions. For the intended policy verify `execution_mode: paired_structure`, `entry_route: market_next_quote`, `eligible_timeframes: [M5, M10, M15]`, the above `pairs` and `entry_timing: intrabar_cross` (or `by_route`). Edit only the necessary keys in the existing `hull:` section. No config change touches an existing ticket or authorizes arming. If there is no private file, you can test `config.yaml` in **paper** mode; never change the shipped template to demo.
4. **Check the interpreter and run the actual read-only preflight.** From the same checkout, using its venv with this checkout installed editable and the MT5 package available:

   ```powershell
   $py = '.\.venv\Scripts\python.exe'
   $sha = Read-Host 'Paste the FULL published Hull commit SHA'
   $cfg = if (Test-Path -LiteralPath .\config.demo.local.yaml -PathType Leaf) { '.\config.demo.local.yaml' } else { '.\config.yaml' }
   & $py -B .\tools\preflight_release.py --expect $sha --config $cfg
   if ($LASTEXITCODE -ne 0) { throw 'Release check or MT5 preflight failed. Do not arm.' }
   ```

   The checker refuses the wrong commit, uncommitted/untracked work outside ignores, a foreign Python import, or a different timing/mapping. It does not insert `src` on `PYTHONPATH`, edit settings, fetch Git or use Journal controls. If `bot` imports from another checkout, fix the intended `.venv` using this checkout's editable install **after** verifying it isn't shared with a running process. For a portable ZIP without Git history use its `SHA256SUMS.txt`, then normal `hull-preflight`; the Git release checker deliberately requires a checkout.

5. **Report facts separately from readiness.** Verify `mode: READ ONLY`, `checkout_head_at_start`, `source_module`, account/magic, `entry_timing: intrabar_cross`, `parent_to_trigger: {M5: M4, M10: M8, M15: M12}`, and `pair_history_ready: true`. M4 and M12 are native MT5 clocks; M8 requires consecutive M4 bars and the broker D1 anchor. For each enabled symbol report `lots`, base `target_usd`, `target_preview_by_side` for BUY/SELL, session status, open positions, pending orders and every `review_before_demo` warning. A fresh quote is not proof of a fill; report any missing preview or bar instead of substituting another timeframe or disabling a safety check. Passing preflight is **not** approval to arm. If a separate verified demo start is wanted later it needs its own explicit authorization.

**Offline regression commands** (from that same verified checkout): `& $py -B -m pytest -q` and `& $py -B -m pytest -q HullJournal/tests`. The focused new acceptance suite is `tests/test_hull_shipped_pairs.py`; continuous valid-tick/veto replays are in `tests/test_hull_valid_ticks.py`. Do not delete tests or bypass `cross_region_unavailable`: valid entries require a provable Hull intersection.
