# Dynamic Hull: signal, entry and exit

The scanner and [FC DynHull Pine v6](../indicators/FC-Hull-Dynamic-Source.pine) share the raw Hull cross and confirmed structure calculation. The post-MSS entry rule differs: the latest Pine indicator allows the first aligned cross, while `trade`, `demo` and `trade-all` retain the bot veto described below. The older Either/16 charts and v4 closed-label benchmark are historical tools, not signals for this bot.

**Timeframes pending.** `hull.eligible_timeframes: []` blocks preflight, observation and arming before MT5 is initialized. Neither symbol profiles, `data.timeframes` nor `--timeframe` grant permission. Once the operator supplies the list, a flag can narrow it, never expand it. Do not interrupt an existing manager to install this change.

| Confirmed structure | Fresh raw Hull BUY | Fresh raw Hull SELL |
|---|---|---|
| Bullish | Close owned shorts first; a new BUY is eligible if flat | Close owned longs; no new short |
| Bearish | Close owned shorts; no new long | Close owned longs first; a new SELL is eligible if flat |
| Neutral | Close owned shorts only | Close owned longs only |

**Bot only: after each confirmed MSS/CHoCH, skip exactly the first trend-aligned Hull cross on each signal lane.** A matching cross on the shift close counts as first. INIT/BOS do not arm or reset this rule; opposite raw signals still exit and do not spend it. The skipped bar stays blocked on every tick and at its close. A later distinct aligned cross is eligible, subject to normal order checks. A raw bot signal with an unusable initial stop is not an otherwise-valid candidate and does not use the skip. The first candidate is counted as a signal, not a fill; a desk/risk veto never refunds it.

No midpoint, discount/premium, swing-zone, EMA or later-BOS requirement at the signal **or** on the quote used for a ticket. INIT/BOS/MSS, a wick touch, or bias alone is never an entry or an exit signal. The execution desk still requires a valid original SL and all existing order protections for **new** entries.

## Calculation and clocks

- Shared base length **16** for Hull A and Hull B. The bot requires 16. Pine’s Length input defaults to 16 for the chart and all three session-statistics timeframes. Build the full Low and High Hull A series separately. Select Low in bullish structure, High in bearish structure. While neutral, `neutral_mode: high` matches Pine; `wait` suppresses raw signals there. B always uses close. Strict BUY means B > A now and B < **the same source’s** A on the preceding completed chart candle; SELL is the strict inverse. Switching source alone cannot manufacture a crossover. Fixed Pine OHLC-derived sources are supported; `custom` can map to a named local price source, not an external TradingView study feed.
- `structure_timeframe: null` is the indicator’s **Chart** setting: independent state per symbol and signal timeframe. Optional higher-TF bias is published only from a native close available at the chart bar’s **open**. A nested lower timeframe processes only finished structure bars, up to the observed tick for live charts. The override does not create a trading lane.
- The default swing has three bars on either side. Structure tests the previous guard and swing levels by **strict closing price** first, then consumes the newly confirmed pivots. MSS has priority; continuation and failed counter-swings update protection exactly in that order. Pivots from the qualifying break window can arm the new leg. Wicks/equal closes do not reverse the trend. The protected swing is for direction, not a half-range entry test or the initial SL.
- The bot samples a verified native forming bid candle on fresh MT5 quotes; it does not wait for its close. A live cross can disappear later. An independently fresh confirmed close can also qualify. Warm-up/known-at-attachment signals are not trades; the same observed cross cannot re-enter on every tick or again at the close. Different feeds and polling mean Pine and MT5 need not see every identical tick.
- A raw opposite signal requests a market close of **all owned opposite tickets on that instrument** before deciding on a replacement, even if that signal cannot open (wrong trend, invalid initial stop, or new-entry risk veto). A market request is not a guaranteed fill. A stale quote defers the latched close until a usable quote; ambiguous replies require reconciliation, never a blind resend. Broker SL/TP stay in place. A replacement needs an independently trend-aligned cross, verified flatness and normal admission. Only entry-qualified signals vote on a replacement. If opposite directions both qualify at the same timestamp, skip the new entry; protective exits are still honored.

## Upgrade the local configuration

Keep the existing broker aliases, lots, risk limits, magic number, ladder and ticket state. In `hull:` use `entry_timing: live_hull_cross` and initially `eligible_timeframes: []`. Under `indicator:` use `source: dynamic`, `hull_len: 16`, `swing_len: 3`, `structure_timeframe: null`, `neutral_mode: high` and `exit_opposite: true`. Remove the retired `signal` and `ema_length` keys. Old `either`, old clock values, or disabling opposite exits are rejected rather than silently changing a running policy. A private YAML is not overwritten, and a running process is not updated by editing these files. If your private YAML explicitly sets `hull.indicator.hull_len` to 24, change that field to 16: config validation rejects a non-16 bot length before the terminal is opened. On an existing TradingView chart, check the saved Length input is 16 and recreate any alerts that used the old setting.

The default initial stop, spread-inclusive per-ticket TP, 70/30 ladder and broker safeguards are documented in the [operating guide](HULL_DEMO.md#which-candle-supplies-the-stop). No performance result is claimed for this replacement.

## Pine win-rate table (not a bot configuration)

The **15m, 30m and 45m columns** each run an independent one-position study on confirmed native candles. With **Chart**, each uses its own structure. A structure override follows the same confirmed-structure clock as the chart. Pine entry labels, alerts and the table all allow the **first** aligned Hull cross after a confirmed shift, including on the shift close. An MSS without a cross is not an entry. Chart alerts can be live; table entries and opposite exits use the signal candle’s close.

### What the rate means

The **Overall** row includes entries both inside and outside the named sessions. For each cell, `W` = proven TP first, `L` = proven non-win, `U` (`?`) = definitely finished but TP versus break-even order is unknown. `n = W + L + U`. With no unknowns the table shows `W/n`; otherwise it shows **`W/n` to `(W+U)/n`**, with percentage endpoints rounded outwards to one decimal place. This is a bound on the **counted trades**, not a confidence interval, a tick replay, or a bound on hypothetical extra entries. **All TFs** sums counts *before* dividing; it is not an average of percentages or a portfolio of unique fills. Hover any rate cell for its counts. An open or possibly open position is not in the denominator.

`— (0)` means valid data but no finished trades. `n/a` means no usable native closes in the date window, a non-nested structure override, or missing TP sizing that prevents a complete study. A pooled rate requires all three books to be usable. Set **Test from / Test through** to compare a common interval; hover the coverage row for each timeframe’s actual first and last in-window closes.

Session membership is recorded at the **entry close timestamp**, not the exit. Defaults match the project's session clocks and are editable in the Pine settings: Asian 00:00–07:00 UTC; London 08:00–16:00 London time; New York 08:00–17:00 New York time; NY–London killzone 13:00–16:00 London time **while both local sessions are open**. The two city clocks follow their own daylight-saving schedules. Start times are inclusive; end times are exclusive. Overlap entries can appear in London, New York and the killzone, but count only once in Overall on that timeframe. These are reporting tags, not entry filters.

### How an exit is counted

1. The fill is the **confirmed signal close**. No wick from the entry candle can touch that trade’s TP or break-even (BE). Each timeframe permits one held trade.
2. For a held position, evaluate the next native candle’s **1-minute candles in time order** (optional: 5m). Use them only when they span the native bar with sane OHLC, no time holes and matching aggregate OHLC. Missing or inconsistent lower history uses the **whole native candle**; never accept an apparent early hit from just a partial list. The coverage row reports the fraction of evaluated held bars with complete lower data, not the fraction of known outcomes. No order of highs and lows is assumed inside the smallest usable candle.
3. TP reached first is a win. BE is immediate by default: an unchanged opening print at entry is **not a retest**; trading through the adverse side or a proven return after leaving entry is. A positive BE percentage arms it only **after a favorable native signal close** reaches the threshold, never from a minute close or wick. A raw opposite Hull signal at the native close before either price exit is a loss, even at a favorable price. A gap already through a level resolves at the first observable price unless an earlier stop is still possible.
4. If both exits fit the observations and the trade must be flat, count `?`, not a loss or a win. If BE **might** already have happened but the position **might** still be open, reserve its slot and carry the uncertainty forward (`BUY?` / `SELL?`). At the date cutoff this is a held slot, **not** a completed unknown. Do not create hypothetical re-entries during this period; hover Position for the number of otherwise aligned same-side signals withheld. If all possible paths end at BE or an opposite close, that is a **definite loss**; distinguish “BE or opposite” from an opposite-only exit in the TP / Loss / ? tooltip.

**Inspect a chart example:** enable *Mark counted test entries and exits* on a standard 15m, 30m or 45m chart. Orange = entry-close price, cyan = its target. `TP`, `BE`, `L` or `?` marks the native candle in which the held case resolved, not an exact execution tick. A reversal can mark an old exit and a new entry on the same close. Compare the marks with lower candles on the same feed. TradingView plan/history limits, missing minutes and feed differences can change coverage and results.

### USD target versus price distance

Set the lot size and **gross** USD target. Auto uses TradingView’s symbol metadata and currency conversion, not an MT5 contract lookup. To match a broker, enter the **profit tick value in USD at 1.00 lot** and the **price size of that tick**. Broker tick size defaults to the chart minimum tick when left at zero. `brokerTicks = ceil(target USD / (lots × USD per broker tick at one lot))`; `chartTicks = ceil(brokerTicks × brokerTickSize / chartMinTick)`. Round up to a reachable chart tick. The separate broker **point size** only converts that distance for display: `points = chartTicks × chartMinTick / pointSize`. The **TP Δ / pts** row displays *price distance / points*; hover it for the last fill and target prices.

For example, **if** one lot earns $1 per 1.00 Nasdaq price move, a $5 gross target from 25,000 is 25,005 for a BUY (24,995 for a SELL). With a 0.10 display point, the row shows `5.0 / 50`. Another contract can give a different distance. The indicator models chart prices, not executable bid/ask ticks, spread, slippage, fees, the bot’s real SL or its profit ladder. These comparison intervals do not authorize any live bot timeframe. Only fabricated candles are used in [the code contract](../tests/pine/hull_stats_contract.cjs); no market backtest or performance result is supplied.
